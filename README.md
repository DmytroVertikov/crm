# CRM по резиденциям

Кликабельный прототип: база клиентов, этапы дел по резиденциям, дедлайны и напоминания.

- Один экран: список клиентов слева, вкладки с карточками по центру, контакты справа.
- Вкладка «Сегодня» собирает сводку и напоминания. Плитки сводки работают как фильтры.
- Данные хранятся в тестовом проекте Supabase (PostgreSQL). Если он недоступен, работает от localStorage браузера. Сообщения клиентам никуда не отправляются.

Запуск: откройте `index.html` в браузере. Работает без сборки и сервера.


## Тестовая база данных

`db/schema.sql` — схема SQLite (клиенты, дела, заметки, вид `v_deadlines`). `python3 db/seed.py` создаёт `db/crm_test.db`: 30 вымышленных клиентов, даты считаются от сегодняшнего дня. Перезапустите скрипт, чтобы сдвинуть сроки.

### Supabase

`index.html` читает и пишет данные через REST-API проекта `crm-residencias` (схема `db/supabase/schema.sql`, данные `seed.sql`). Доступ с публичным ключом открыт политиками `db/supabase/test_anon_access.sql` и годится только для вымышленных данных: любой, у кого есть ссылка на страницу, может их менять. Перед работой с реальными клиентами нужны вход пользователей и политики для роли `authenticated`.

### Карточка клиента

Поля «Цель и этап дела» и «Миграционный статус клиента» берут варианты из `config/crm_options.json` (испанские названия рядом с русскими). Список оснований зависит от административного статуса. Те же данные встроены в `index.html` (переменная `OPT`): при изменении JSON обновите её. Значения хранятся в колонках таблицы `clients`.

### Шапка карточки

Гражданство (список в `config/countries.json`, русские и испанские названия), NIE с проверкой контрольной буквы (предупреждает, но не блокирует), основной и дополнительные телефоны. Под основным телефоном есть флажок «WhatsApp на этом номере» (колонка `clients.phone_whatsapp`, миграция `db/supabase/add_phone_whatsapp.sql`). Если он отмечен, рядом появляется ссылка «Открыть чат» (`wa.me`): номер без кода страны считается испанским (+34). Сообщение менеджер отправляет сам. На вкладке «Сегодня» у напоминаний клиентам, у которых отмечен WhatsApp, есть кнопка «Открыть в WhatsApp»: чат открывается с уже подставленным текстом напоминания. Поля со списками принимают только варианты из конфигурации; «Главная цель» и «Следующий шаг» принимают любой текст, список для них только подсказывает (`text_suggestions` в `config/crm_options.json`).

## Сохранение карточки

Правки полей карточки хранятся в черновике: ни в браузер, ни в Supabase они не уходят, пока не нажата кнопка «Сохранить» (панель появляется внизу страницы только при изменениях, также Ctrl+S). «Отменить» возвращает прежние значения. Несохранённая карточка помечена точкой на вкладке, при закрытии вкладки и страницы приложение предупреждает. Действия с делом (открыть дело, запрос, решение) и примечания сохраняются сразу.

## Справочник опций

Вкладка «Справочник» (рядом с «Сегодня») позволяет править варианты шести списков: административный статус, основание, стадия, тип документа, главная цель, следующий шаг. Можно переименовывать (по-русски и по-испански), менять порядок (стрелки, перетаскивание, сортировка А–Я / Я–А), добавлять и удалять варианты, а для оснований выбирать, при каких статусах они показываются. Применяется кнопкой «Сохранить»; хранится в браузере и в таблице `app_settings` в Supabase. «Вернуть исходный справочник» восстанавливает варианты из `config/crm_options.json` (встроены в `index.html`).

## База данных

Кнопка «База данных» рядом со «Справочником» открывает служебную страницу с операциями резервного копирования: «Сохранить копию в JSON» выгружает данные CRM в файл, а «Загрузить копию из JSON» восстанавливает их из выбранного файла. Импорт заменяет текущие данные и перед выбором файла запрашивает подтверждение. «Очистить базу» удаляет клиентов и связанные дела; перед удалением требуется подтверждение, после чего изменения синхронизируются с Supabase. Открытие страницы само по себе данные не меняет.

## Лента дела

Разделы «Дело» и «История и примечания» объединены в одну ленту на клиента: дата, действие, комментарий.
Тип записи выбирается кнопками: Событие по делу (Подача заявления, Запрос дополнительных документов, Предоставление документов в ответ на запрос, Получение решения — каждое «миграционной службы»), Общение (тип контакта: исходящий/входящий звонок, исходящее/входящее сообщение, встреча; канал связи; необязательный результат общения), Запланировать, Заметка. Записи можно править и удалять.
Статус, шаги дела и напоминания считаются из ленты. Таблица `case_log` в Supabase (см. `db/supabase/schema.sql`);
старые данные из `cases` и `notes` перенесены в неё, старый формат localStorage конвертируется при загрузке.

Запланированные шаги: действие «Запланировать» создаёт запись на будущую дату (поле «Что сделать» + комментарий).
Ближайший невыполненный шаг показывается как «Следующий шаг» в списке клиентов и в карточке; кнопка ✓ отмечает его выполненным.
Отдельных полей «Следующий шаг» и «Комментарий к следующему шагу» в карточке больше нет (колонки в `clients` остались пустыми).

## Вкладка «Сегодня»

- Блок «Мои задачи» собирает невыполненные записи «Запланировать» по всем клиентам: «Просроченные», «Сегодня» и «Будущие» (раскрывающийся список, свёрнут). Кнопка «Выполнено» закрывает задачу. Пока нет входа пользователей, показываются задачи всех менеджеров.
- Плитка «Срочно» считает уникальных клиентов с хотя бы одним срочным основанием: статус дела, срок резиденции до 30 дней или просроченная задача. Цифра на вкладке «Сегодня» — это те же клиенты плюс клиенты с задачей на сегодня. Клик по любой карточке ленты открывает клиента (кнопки внутри карточки работают как раньше).
- Срок резиденции контролируется независимо от дела: если дело открыто, напоминание всё равно появляется (без текста клиенту), в левом списке рядом показан срок.
- Плитка «Дел в работе» считает клиентов с открытым делом (подано, решения нет). Все плитки и фильтры, включая «В работе» и «Закрытые», фильтруют и список, и ленту. Принадлежность клиента к «Срочно», «Ждут ответа» и «Продление» определяется одним правилом (`reasonOf`): клиент в плитке и в списке, если у него есть карточка в ленте по этому фильтру. Для «В работе» и «Закрытые» над лентой показано, у скольких клиентов из списка есть карточки.

## Список клиентов

- Поиск работает по имени, номеру дела, телефону (основной и дополнительные, по цифрам от 3, формат не важен) и NIE (без учёта регистра, пробелов и дефисов). Если клиент найден по телефону или NIE, в строке списка показано, что совпало.
- Сортировка: «Сначала срочные» (по умолчанию), «Давно без активности» (клиенты без записей в ленте идут первыми), «Недавняя активность». Активностью менеджера считаются: записи ленты (по их дате), создание задачи, выполнение задачи (с датой выполнения) и осознанный перенос задачи. Автоматический пересчёт статусов и сроков активностью не считается. У задачи в журнале видно «создано», «перенесено» и «выполнено» с датами (колонки `created_on`, `done_on`, `moved_on` в `case_log`, миграция `db/supabase/add_task_activity_dates.sql`). Возврат задачи в план убирает дату выполнения. У задач, созданных до этого изменения, дат нет, поэтому активностью они не считаются.
- «+ Новый клиент» открывает форму с полем имени и кнопками «Добавить» и «Отмена» (также Enter и Esc). При совпадении имени с существующим клиентом приложение спрашивает подтверждение. После добавления карточка открывается с курсором в поле телефона.

## Если нет связи или сервер вернул ошибку

- «Сохранено» показывается только после подтверждения от Supabase. При ошибке или без интернета выводится «НЕ сохранено на сервере», а в шапке остаётся красная надпись, на которую можно нажать для повторной отправки. Повтор идёт и сам: при появлении связи и раз в 30 секунд.
- Неотправленные изменения хранятся в браузере с пометкой. При следующем открытии приложение спросит: отправить их на сервер или загрузить данные с сервера (тогда несохранённые правки уйдут в резервную копию `crm-residencias-v1-unsent` в localStorage). При отправке клиенты, добавленные на сервере за это время, не удаляются.
- Закрыть страницу с неотправленными изменениями браузер не даст без предупреждения. То же относится к справочнику.
- Известное ограничение: при сохранении клиента его лента на сервере удаляется и записывается заново. Если связь пропадёт между этими шагами, на сервере временно будет неполная лента, пока изменения не отправятся повторно. Данные при этом остаются в браузере. Окончательно это решается сохранением отдельных записей (см. план по аудиту и входу пользователей).
